# Project rules
- Trigger slider navigation hints only when the untouched marker enters view, animating the whole marker (disc and its inner arrow together) but never the saved answer; the deck keeps offscreen cards mounted, so mount-time animations would finish unseen.
- Keep additional reflection-style slides in focused components using the existing notes persistence and print flow, so data clearing and exports remain consistent.
- Use Radix Slider for the relationship-work scale so pointer, touch and keyboard input share accessible, bounded behavior.
- Normalize workload shares with shared pure helpers and persist all changed partners in one state update; screen and print use the same normalized split to avoid mismatched totals.
- Represent workload as contiguous percentage-width segments; move adjoining boundaries with Radix sliders and reserve a separate avatar slot for each partner so zero shares cannot cause overlap.
- Paginate Risikofaktoren one statement per card using one shared notes namespace, so extra pages preserve existing values and follow the same print and clearing flow; the split stays parameterised so a caller can ask for more per card and a short card drops to fewer rather than clip.
- Type the Risikofaktoren statement in the big question's own voice by listing it in the shared `#root` question-font rule — a plain class rule loses to the global `#root *` typography — and let it carry only its own smaller size, stepping down on narrow phones so the scale and its lane stay reachable.
- Morph shared face geometry through the current Risikofaktoren header expressions without opacity blending, so draggable markers match every evenly spaced scale anchor continuously.
- Size each printed page to the printable area (not the full sheet or the screen viewport) and anchor the print container to the sheet top, so every card lands on its own page without overflow or a blank first page.
- Keep absolutely positioned card content inside the card's own content box — clamp with CSS `min()` against the container and measure the live container while dragging — so nothing can make a card horizontally scrollable.
- Compute Health Check smiley-click positions with a shared geometry helper using live face bounds; preserve the clicked face anchor for print and clear it on free drag so both outputs keep the intended alignment.
- Let a scale span its container edge to edge and keep the handle inside by insetting its travel by the handle's own radius, pulling the faces and end labels in by the difference — never by marginning the whole scale in, which would leave the line short of the card edges.
- Sit the Risikofaktoren smileys flush with the field's top edge (no stub above them) and centre the rule on the long dashed guide's span: the field's top padding equals the guide's start, so the flex centring lands the rule on the line's own midpoint at every field height, on screen and in print.
- A slider handle's decorative contents (avatar, label) must let the pointer through, and any slider whose root ignores pointer events needs its own pointer handler on the container — reading the live handle positions, capturing the pointer and locking the handle it picked — plus touch-none and card-deck paging suppression, so a press anywhere drags the nearest handle instead of only working on the handle itself. On a single-marker scale, leave only the marker itself to the slider and let the container's handler place it on a press anywhere else in the field, including the rule's outer ends that the slider's own inset track does not reach.
- Keep both scales on one shared field height (`--risiko-field-h`): it caps the statement scale's field on screen and sets the work-split lane's height, and the lane centres its bar, dots and names on its own height with `cqh` (size containment) so the printed card can stretch the lane without any of them coming loose.
- Draw the Risikofaktoren columns as dashed divider lines between neighbouring columns only — the scale's own left and right edges stay bare — rather than as filled bands, and keep the column names in a flow row under the field (not absolutely pinned inside it), so the guides end exactly where the names begin on every width and on paper.

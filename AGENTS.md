# Project rules
- Trigger slider navigation hints only when the untouched marker enters view, animating the whole marker (disc and its inner arrow together) but never the saved answer; the deck keeps offscreen cards mounted, so mount-time animations would finish unseen.
- Keep additional reflection-style slides in focused components using the existing notes persistence and print flow; reuse the Health Check scale by rendering its exported `StatementScale` inside a `.risiko-page` host, and lower the field's floor when a card shares its height.
- Migrate moved answers against storage at startup and save at once; card state only persists after an edit, so the card opened first would erase what the other needs.
- Use Radix Slider for the relationship-work scale so pointer, touch and keyboard input share accessible, bounded behavior.
- Normalize workload shares with shared pure helpers and persist all changed partners in one state update; screen and print use the same normalized split to avoid mismatched totals.
- Represent workload as contiguous percentage-width segments; move adjoining boundaries with Radix sliders and reserve a separate avatar slot for each partner so zero shares cannot cause overlap. Each circle steps 2px away from the boundary it rides (thumb transform / readOnly left calc, as Radix positions its own wrapper) so neighbours keep a 4px gap and a solid ink boundary line exactly as tall as the grey guides centres in that gap. Name each partner in a row above the circles, print its share in one below, both centred on its colour run, clamped inside the lane and clear of the circles; both use `width: max-content` under a fixed `max-width`, so a narrow run can neither squeeze a name nor push a number off the card.
- Paginate Risikofaktoren one statement per card using one shared notes namespace, so extra pages preserve existing values and follow the same print and clearing flow; the split stays parameterised so a short card drops to fewer.
- Type the Risikofaktoren statement in the big question's own voice by listing it in the shared `#root` question-font rule — a plain class rule loses to the global `#root *` typography — and let it carry only its own smaller size, stepping down on narrow phones.
- Morph shared face geometry through the current Risikofaktoren header expressions without opacity blending, so draggable markers match every scale anchor.
- Size each printed page to the printable area (not the full sheet or the screen viewport) and anchor the print container to the sheet top, so every card lands on its own page without overflow or a blank first page.
- Keep absolutely positioned card content inside the card's own content box — clamp with CSS `min()` against the container and measure the live container while dragging — so nothing can make a card horizontally scrollable.
- Compute Health Check smiley-click positions with a shared geometry helper using live face bounds; keep the clicked anchor for print and clear it on free drag.
- Let a scale span its container edge to edge and keep the handle inside by insetting its travel by the handle's own radius, pulling the faces and end labels in by the difference — never by marginning the whole scale in, which would leave the line short of the card edges.
- Sit the Risikofaktoren smileys flush with the field's top edge and centre the rule on the long dashed guide's span; draw the lines against a stack holding field and names, the stack being the face row's positioning parent, and give each name a plate of the card's surface so no line draws through its letters.
- A slider handle's decorative contents (avatar, label) must let the pointer through, and any slider whose root ignores pointer events needs its own pointer handler on the container — reading the live handle positions, capturing the pointer and locking the handle it picked — plus touch-none and card-deck paging suppression, so a press anywhere drags the nearest handle. On a single-marker scale, leave only the marker itself to the slider and let the container's handler place it on a press anywhere else in the field, including the rule's outer ends the inset track does not reach.
- Keep both scales on one shared field height (`--risiko-field-h`): it caps the statement scale's field on screen and sets the work-split lane's height, and the lane centres its bar, dots and names on its own height with `cqh` (size containment) so the printed card can stretch the lane without any of them coming loose.
- Centre the Risikofaktoren slider with a fixed scale height and an even split of the free space, closing the last pixels with a shift that halves the room between the text above and the buttons below — the scale's block, note included, stands there, clamped to the room, read on screen only, and given to the clip's own element. A note on the scale rides inside that block, screen-only, keeping its press and the card's padding as its gap.
- Pass a shared row component's label as one element: its label field lays its children side by side, so a bare fragment splits a sentence into columns.
